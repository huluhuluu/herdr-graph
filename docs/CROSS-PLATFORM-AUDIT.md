# Windows / Linux 深度审查

日期：2026-10-21。范围为当前未提交的 Session Graph 修改及安装、扫描、目录树、缓存、原生进程和弹窗路径。

## 已复现并修复的问题

| 问题 | 影响与证据 | 修复 |
| --- | --- | --- |
| 窗格启动时改写 agent 目录 | Windows 原生插件窗格启动 shell 会执行 profile；实测打开动作使用测试目录，窗格却改为另一个 `CODEX_HOME`，导致扫描错目录、`c` 和 `[current]` 失效 | 打开时解析并固定三类 agent 的绝对根目录；窗格恢复后再创建 worker 和执行原生操作。只传递已知三个变量，不导入任意环境键 |
| 错误元数据中断扫描 / 关系显示 | `cwd` 对象会使目录规范化抛异常并终止该 agent 的后续扫描；对象形式的父会话 ID 会使短 ID 计算失败 | 三个适配器在元数据入口校验关键字段类型；保留错误条目，其余会话继续加载。真实 worker 回归同时包含三类 agent 的错误记录与正常记录 |
| 大首行遮住后续 Claude 元数据 | 初始文件快照超过读取块时，旧实现裁掉首行之后的数据；目录、标题和父会话可能缺失 | 保留已读取的后续前缀，边界处最多再读一块，不无限追读大工具输出。覆盖首行恰好 256 KiB、300 KiB、512 KiB |
| 深分叉使目录列表栈溢出 | 12,000 层父子会话触发 `RangeError` | 目录树改为迭代遍历；折叠的后代仍标记已遍历，避免作为孤立根重新出现 |
| Linux 缓存权限过宽 | 在普通 umask 下新缓存文件为 `644`、新目录为 `755`；父目录允许遍历时，完整问答可能被同机其他用户读取 | 新文件 `600`、新目录 `700`；读取旧普通缓存时收紧权限。独占创建暂存文件，保留冲突文件，失败时清理自己的暂存文件；不 chmod 符号链接的目标 |

缓存字段和对话解析语义没有变化，无需更换缓存版本。新增检查涵盖已有缓存权限、暂存冲突、替换失败、符号链接目标保护、深树折叠、坏元数据扫描隔离和根目录交接。

## 原生 Codex 超时与资源使用

本机 Codex 已更新到 0.163.0。隔离 App Server 的协议跟踪显示：无模型配置时，初始化后仍会加载模型目录；本地诊断日志包含 `online_if_uncached`、无可用模型缓存，以及远程插件目录预热请求。一次小会话分叉约 20.5 秒完成，耗时主要发生在请求阶段而非退出阶段。

临时配置明确指定本地测试 provider 后，同类分叉约 2 秒完成。原生测试现在使用这类临时配置，目标为不提供模型服务的本机回环端口；不发送模型轮次，不更改用户 provider。测试记录也补齐原生 `task_complete.turn_id`。

这确认了测试空配置存在额外初始化依赖，不能据此证明之前每一次超时都有相同原因。生产仍保留 60 秒单次期限，不自动重试分叉；用户实际 provider 的冷启动和网络依赖仍可能影响原生操作。

插件只需要新会话 ID，因此 `thread/fork` 使用 `excludeTurns: true`，避免将完整历史再传回插件。该参数已核对 Windows 0.163.0 和 Linux 0.160.0 生成的原生 schema；真实测试继续验证新会话已保存、可读、带父链且原会话不变。

Windows 完整结果为 **155 项通过、0 失败、0 跳过，约 53.6 秒**；最终相对根目录交接的调整另外通过了两项针对性回归。

Linux 最终结果为 **155 项通过、0 失败、0 跳过，约 20.0 秒**。两端全部源码和测试文件按 LF 统一换行后的 SHA-256 一致。

所有改名和分叉仅使用临时会话。测试配置与服务不替换默认 Herdr 配置和服务。三种 agent 的真实交互式恢复流程、不同 Linux 发行版与 macOS 不属于本次已验证范围。
