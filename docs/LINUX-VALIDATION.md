## 管理脚本

以下命令均实际调用 Herdr CLI，配置修改均通过原生校验和重载：

| 操作 | 验证内容 |
| --- | --- |
| `sh -n install.sh`、`--help` | shell 语法、帮助输出与退出码正常 |
| `install` | 注册本地仓库、启用插件、安装托管快捷键并创建配置备份 |
| 再次 `install` | 自定义托管快捷键逐字节保留 |

| `remove-keys` / `setup-keys` | 仅移除托管块 / 恢复模板；保留主题配置 |
| `clean` | 清理新旧位置的解析缓存及临时文件；保留其他文件、符号链接和配置 |
| `update` | 本地修改时拒绝更新且保留源码；真实快进更新后保留禁用状态与快捷键 |
| `uninstall` | 移除托管块、注册和解析缓存；保留无关状态、配置备份及仓库 |
| 重复 `uninstall` | 正常结束，最终配置仍通过 `herdr config check` |

## 原生界面与发现的问题

- `prefix+g` 与 `herdr plugin action invoke open --plugin huluhlu.session-graph` 均能打开弹窗。
- 验证了 4 条测试会话的目录列表、中文问答、`s` 历史、`f` Family、`d` 详细树、搜索、`c` 当前对话及 `q` 退出。
- Herdr 未提供原生会话 ID 的测试窗格通过唯一 agent / 目录 / 完整终端标题识别当前会话；`[current]` 显示在图节点中。
- 缩小终端后验证 Family 结构、Tab 全宽正文和返回树。

修复了两项实测缺陷：

1. **从其他项目目录打开后立即退出。** manifest 使用相对路径 `src/graph.js`，原实现把进程工作目录设为调用项目，导致 `Cannot find module`。现在从插件仓库启动，通过 `SESSION_GRAPH_CWD` 单独保留调用项目目录。新增回归检查在旧实现上失败、修复后通过。
2. **标题、计数和正文提示重叠。** 顶部为节点计数预留宽度，第二行按左右栏分配宽度；全宽正文只显示自己的提示。历史在空间不足时优先显示会话和目录总数。回归检查覆盖 58、80、118、160 列，以及历史、Family 结构、正文和详细树。

修正 DST 的版本说明：Node 22.22.0 已提供 `zstdDecompressSync`，压缩会话测试无需跳过。[Node 官方文档](https://nodejs.org/download/release/v22.22.0/docs/api/zlib.html#zlibzstddecompresssyncbuffer-options)记载该能力加入于 22.15.0；支持 22.15+ 的 22.x 或 24+。

## 自动化回归与边界

使用仓库原有的 `npm test`，包含解析、历史、分支、后台加载、生命周期、界面行为、真实 Codex 改名 / 分叉及 DST 租约校验。测试仅有少量单轮 fixture 时会按设计跳过依赖多轮记录的检查；最终完整验证显式使用远端已有的 agent 根目录。

Linux 最终结果：**149 项通过，0 失败，0 跳过，约 20.9 秒**。远端验证的两个源码文件和两个测试文件均与本机最终文件的 SHA-256 一致（统一换行后比较）。

Windows 补充回归（Node.js 24.19.0）：最终以 `--test-concurrency=1` 运行同一套文件，**148 项通过，1 项失败**。失败为真实 Codex `thread/fork` 超过现有 60 秒期限；原生改名 / 分叉的独立复测曾均通过，此前一轮 148 项的串行全套也通过，因此存在间歇性，原因尚未定位。本次未修改 Codex 传输实现；安装器测试及新增两项回归均通过。

以上为首轮验证记录；后续对超时诱因、Windows 原生界面及更多扫描边界的排查与修复，见[双系统深度审查](CROSS-PLATFORM-AUDIT.md)。

没有向用户正在运行的 agent 发送恢复或分叉命令。`n` / `F` 的路由和拒绝条件由自动化测试覆盖；本次没有覆盖三种 agent 交互式 TUI 的完整恢复流程。macOS 仍未进行原生运行验证。

临时插件已卸载。测试服务、专用 tmux 会话和临时目录在验证结束后清理；远端默认 Herdr 服务保持原状态。
